# 物业合同分析智能体 — 设计文档

> 版本: 1.1 | 日期: 2026-08-04 | 状态: 待审核

## 一、项目概述

基于物业合同 PDF 分析的智能体，用于分析成都市多个楼盘的物业是否存在"同价不同服务质量"和"同服务质量但价格不同"的情况。

### 数据基础

| 数据源 | 内容 | 格式 | 说明 |
|--------|------|------|------|
| 成都市住宅物业服务等级规范 | 5 个等级、7 个大类、200+ 条明细，含"同比上一级新增"标记 | Excel | 已结构化 |
| 天府新区 74 个楼盘物业合同 | 30-40 页 PDF，含完整的物业服务条款 | PDF | 需全文解析提取服务条款 |
| 合同元数据表 | 物业名称、位置、建筑面积、物业类型、甲方、乙方、住宅/商业/车位费用 | Excel | 已结构化，仅基础字段，**不含服务条款** |

**关键约束**：74 份 PDF 是主数据源——服务条款分散在各章节中，必须从 PDF 中提取。现有 Excel 只有物业名称、价格等元信息，可作为 PDF 提取后的字段补充和校验源。

### 功能模块

1. **同价不同质**：两个价格相近的合同，对比各自满足规范条款的差异
2. **同质不同价**：批量分析，按满足度聚类后找出价格异常楼盘
3. **满足率计算**：计算单个或多个合同对五级规范的满足率

## 二、技术选型

| 维度 | 选择 | 理由 |
|------|------|------|
| 交付形式 | Web 应用 | 浏览器操作，直观对比分析 |
| 前端框架 | Streamlit | 快速开发，原生表格/图表支持，Python 生态无缝 |
| 后端语言 | Python 3.11+ | 团队技术栈一致 |
| 匹配方式 | 规则粗筛 + LLM 语义判定 | 平衡准确性（LLM）和成本/速度（规则） |
| LLM 支持 | DeepSeek / Claude / OpenAI / 自定义 | 多模型可切换，页面配置 |
| 价格阈值 | UI 可调 | 用户按需调整 ±% 和 σ 倍数 |
| PDF 预处理 | 前置预处理 + 分级缓存 | 静态数据一次性处理，后续分析秒级响应 |
| 配置存储 | JSON（`data/config.json`） | 程序自动读写，用户不接触文件 |

## 四、数据模型

### 4.1 标准规范项 `StandardItem`

```python
@dataclass
class StandardItem:
    id: str              # "L3-C2-045"（等级-大类-序号）
    level: int           # 1~5
    category: str        # 综合管理/共用部位维护/共用设施设备维护/公共秩序维护/保洁服务/绿化养护/其他
    requirement: str     # 具体内容和要求
    is_new_vs_prev: bool # 是否同比上一级新增
```

### 4.2 物业合同 `Contract`

```python
@dataclass
class Contract:
    id: str
    # ── 来自 Excel 元数据表 ──
    property_name: str
    location: str
    building_area: float
    property_type: str
    party_a: str
    party_b: str
    residential_fee: float    # 元/月·㎡
    commercial_fee: float
    parking_fee: float        # 元/月·个
    
    # ── 来自 PDF 提取 ──
    service_level_declared: Optional[str]  # 合同中声明的服务等级
    service_clauses: list[ServiceClause]   # 提取的服务条款
    source_pdf: str                        # 原始PDF文件名

@dataclass
class ServiceClause:
    content: str              # 条款原文
    category: str             # 归属大类（综合管理/保洁/…）
    page: int                 # 来源页码
```

**双源合并逻辑**：
1. Excel 元数据表按 `property_name` 匹配 PDF 文件名
2. PDF 提取出 `service_clauses` 后，合并到已有 Contract 对象
3. Excel 中的价格字段作为权威值，PDF 中提取的价格用于交叉校验

### 4.3 匹配结果 `MatchResult`

```python
@dataclass
class MatchResult:
    contract_id: str
    standard_item_id: str
    verdict: Literal["满足", "部分满足", "不满足", "不确定"]
    evidence: str            # 合同中匹配到的原文片段
    confidence: float        # 0~1
    method: Literal["rule", "llm"]
    matched_level: int       # 该条款实际达到的等级
```

## 五、核心模块设计

### 5.1 匹配引擎（`engine/matcher.py`）

**两阶段流水线**：

```
合同条款 → [阶段1: 规则粗筛] → 确定 → 直接打标 (method="rule")
                    ↓ 不确定
              [阶段2: LLM语义判定] → 满足/部分满足/不满足 (method="llm")
```

**阶段1 规则类型**：

| 规则类型 | 原理 | 示例 |
|---------|------|------|
| 关键词命中 | 规范要求的关键词在合同中存在 | "24小时值班" → 合同含"24小时""值班" |
| 反向排除 | 合同明确排除了某服务 | "不含绿化养护" → 绿化类全部标记"不满足" |
| 数值范围 | 频率/时长类数值比较 | "每日1次" vs "每周2次" → 不满足 |
| 等级推断 | 合同声明了服务等级 | "按三级标准执行" → 三级以下全部预标记满 |

阶段1 置信度 ≥ 0.9 → 直接写入结果；否则进入阶段2。

**阶段2 LLM 判定**：

Prompt 模板：
```
你是物业合同合规审查专家。请判断以下合同条款是否满足规范要求。

规范要求：{standard_item.requirement}
合同条款：{contract_clause}

判定标准：
- 满足：合同明确覆盖了规范要求的服务内容和频率
- 部分满足：覆盖了服务内容但频率/范围不足
- 不满足：合同未涉及或明确排除

以JSON返回：{"verdict", "evidence", "confidence", "reasoning"}
```

**性能优化**：
- 批处理：20 条/次 LLM 调用
- 缓存：`(规范条款ID, 合同条款原文)` MD5 为 key，7 天有效期
- 阶段1 预期覆盖率：60-70%

### 5.2 PDF 结构化提取（74 份全量处理）

**两步提取**：

| 提取内容 | 方法 | 说明 |
|---------|------|------|
| 元数据字段 | 优先用 Excel 元数据表 | 名称、价格等已结构化，直接读取 |
| 服务条款 | 从 PDF 全量提取 | 这是匹配引擎必需的主数据 |

**三步流水线**（每份 PDF 2 次 LLM 调用）：

```
步骤1: 文本提取 + 文档树构建（pdfplumber/PyMuPDF，秒级）
    输入：30-40页PDF
    输出：章节目录树 + 全文文本
         ├── 第一章 总则
         ├── 第二章 物业服务内容与标准  ← 目标
         ├── 第三章 物业费用
         └── ... 
    ↓
步骤2: LLM语义定位 → 找到"物业服务内容"章节（1次LLM调用）
    输入：章节目录树 + 每章首段摘要
    输出：目标章节编号 + 页码范围
    仅取 5-8 页服务条款章节，大幅减少后续Token
    ↓
步骤3: LLM结构化提取 → service_clauses[]（1次LLM调用）
    输入：目标章节全文
    输出：[{content, category, page}, ...]
    七大类自动归类（综合管理/共用部位/共用设施/公共秩序/保洁/绿化/其他）
```

**全量处理估算**：
- 74 份 PDF × 2 次 LLM 调用 = 148 次（提取阶段）
- + 匹配引擎不确定项判定 ≈ 62 次
- **合计 ≈ 210 次 LLM 调用，10-15 分钟**

**步骤1 — 文档树构建**：

| 信号 | 判定为 | 示例 |
|------|--------|------|
| 字体 > 16pt / 加粗居中 | 一级标题（章） | "第三章 物业服务" |
| 字体 14-16pt / 加粗 | 二级标题（条） | "第一条 综合管理" |
| 编号模式 `第X章/第X条` | 按章/条拆分 | 正则匹配 |
| 无标题但含表格 | 提取为结构化数据 | 费用表、服务频次表 |

**步骤2 — 语义定位**：LLM 读取章节目录树，自动判断哪些章节包含服务条款和费用信息，不依赖固定章节编号。

**步骤3 — 结构化提取**：仅将定位到的 5-8 页目标章节送 LLM，一次性提取所有 Contract 字段。

**成本**：每份新合同 2 次 LLM 调用（定位 + 提取）。

### 5.3 LLM 抽象层（`engine/llm.py`）

```
                    LLMProvider (ABC)
                    + match(requirement, clause) → Verdict
                    + batch_match(items[]) → list[Verdict]
                    + locate_chapters(toc) → ChapterMap
                    + extract_contract(text) → Contract
                         │
          ┌──────────────┼──────────────┬──────────┐
          ▼              ▼              ▼          ▼
    DeepSeekProvider  ClaudeProvider OpenAIProvider CustomProvider
```

- 统一接口，插件式切换
- 配置全部在页面上完成
- 支持连接测试按钮
- LLM 不可用时降级为"不确定"标记，不阻塞流程

### 5.4 缓存管理（`engine/cache.py`）

**预处理流程**（初始化时运行一次）：

```
全部合同 → 规则匹配（秒级）→ 不确定项收集 → LLM批量判定（~62次调用，3-5分钟）
    ↓
merged_results.json（分析模块直接读取）
```

**缓存文件**：

| 文件 | 内容 |
|------|------|
| `merged_results.json` | 所有合同×所有规范条款的完整匹配结果 |
| `metadata.json` | 缓存时间戳、数据版本、合同数量 |

**增量更新**：新增合同时只对新合同跑匹配 + 合并到缓存。

## 六、功能模块详情

### 6.1 同价不同质

**输入**：用户选择 2 个合同 + 费用类型（住宅/商业/车位）

**流程**：
1. 检查价格差是否在阈值内（默认 ±5%），超出则提示确认
2. 分别加载两个合同的完整匹配结果（从缓存）
3. 生成逐项对比表
4. LLM 生成差异摘要

**输出**：
- 对比总表（满足数、满足率、分等级/分大类对比）
- 差异明细（合同A有B无、双方都缺失的条款，可展开看原文证据）
- 雷达图（7大类满足率对比）
- AI 自然语言总结

### 6.2 同质不同价

**输入**：费用类型 + 分析范围（全量/子集）

**流程**：
1. 从缓存加载所有合同匹配结果
2. 计算每个合同的满足度向量 `[总满足率, L1~L5满足率, 7大类满足率]` 共 13 维
3. 余弦相似度聚类（阈值 0.95，UI可调）
4. 同组内检测价格异常（偏离组均值 ≥ 1.5σ，UI可调）

**输出**：
- 满足度矩阵总表（可排序筛选）
- 同质分组列表（每组可展开查看成员和价格）
- 价格异常标红高亮
- 散点图（X轴=满足率，Y轴=价格，异常点红色）

### 6.3 满足率计算

**输入**：单个或多个合同 + 可选按等级/大类筛选

**流程**：
1. 从缓存加载匹配结果
2. 计算总体 + 按等级 + 按大类的满足率
3. 多合同时生成横向对比表

**输出**：
- 满足率卡片（总满足率 + 各等级满足率）
- 水平进度条（按等级、按大类分解）
- 未满足条款可展开明细
- Excel 报告一键导出

## 九、错误处理

| 场景 | 处理方式 |
|------|---------|
| LLM API 不可用 | 匹配引擎降级：不确定项标记"不确定"，UI 红色标注提示用户人工判定 |
| PDF 解析失败 | 提示用户检查文件格式，支持手动录入结构化数据 |
| 缓存过期/缺失 | 引导用户点击"初始化缓存"按钮 |
| 合同数量为 0 | 首页显示引导提示，上传数据入口 |
| 价格差超出阈值（同价不同质） | 弹窗提示确认是否继续对比 |
| 同质组为空（同质不同价） | 提示调整相似度阈值 |
